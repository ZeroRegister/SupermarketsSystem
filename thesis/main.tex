\chapter*{Abstract}\addcontentsline{toc}{chapter}{Abstract}
Small supermarket inventory work combines frequent quantity changes with a need to explain who recorded a change and why. A stock list alone cannot provide that explanation, and a warning that disappears after review cannot distinguish acknowledgement from replenishment. This project develops Shelfwise, a single-store web system that joins catalog maintenance, an auditable movement ledger, and persistent stock-warning episodes.

The implementation uses Java 21 and Spring Boot for the application service, Vue 3 and TypeScript for the browser workspace, MySQL for durable state, and Redis for an optional warning-query cache. Product quantities change only through receiving, dispatch, signed adjustment, or absolute stock-count transactions. A product row lock, a non-negative balance check, and actor-scoped idempotency keys protect ordinary concurrent and duplicate submissions. Warning acknowledgement records a reviewer independently of the warning lifecycle. A database revision namespaces cached warning pages so committed stock and review changes are reflected in subsequent requests.

The evaluation combines container-backed integration tests, authenticated API smoke checks, browser journeys, a Redis outage experiment, a restart persistence check, and an alternating cache/bypass latency measurement. The recorded integration suite covers 27 cases, including threshold equality, role boundaries, duplicate requests, and concurrent dispatch. All recorded cases passed in the local environment. The browser audit confirmed 14 checks with no JavaScript runtime errors. The latency study provides descriptive evidence on a small demonstration dataset; it does not establish production capacity or a business benefit. Redis failure preserved the database-derived warning results, and an application restart preserved the stock and transaction fingerprint.

The main contribution is a reproducible implementation that makes inventory correctness and warning transitions inspectable from code, database records, tests, and interface evidence. Important limitations include whole-unit stock, a single store and application node, a manually maintained threshold policy, and the absence of a real-store usability trial. The work supports a working demonstrator and a basis for further validation rather than a claim of enterprise readiness.

\noindent\textbf{Keywords:} inventory management; stock warning; audit trail; Spring Boot; Vue; MySQL; Redis; reproducibility.
